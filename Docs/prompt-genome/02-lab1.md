# 02 — Lab 1: evolving behaviour on a flat world

Lab 1 opens the course. Students meet a population of animals whose genes are
English sentences, read by an LLM that decides what each animal does. They
run the world, measure it, change genes and watch evolution rewrite them.

The world in Lab 1 is deliberately simple: **flat ground, food scattered
uniformly at random, and a few predators**. In the following labs, students
build terrain and then foliage, and those change the world the animals live
in.

> **Status:** the system exists as the headless Python prototype in
> `prototype/`. The activities below are **proposals** for the course owner;
> sessions, deliverables and grading are not decided yet (§8).

## 1. Why a flat world first

- **One thing at a time.** With no terrain, the only structure in the world is
  food, predators and other animals. Every difference in survival comes from
  behaviour, which comes from the genes.
- **A baseline for the later labs.** Behaviour that evolved on the flat world
  is the reference. When students add terrain and vegetation, they can rerun
  the *same founders* in the *new world* and compare what evolves.
- **Easy to reason about.** Food is uniform, so there are no "good places" to
  find, only good decisions.

## 2. Learning goals

By the end of Lab 1 a student should be able to:

1. Explain the loop **genes (text) → LLM → action probabilities → behaviour →
   survival and reproduction → new genes**, and where randomness enters.
2. Get **structured output** from a local LLM, and say why the output needs
   checking (points that don't add up, all-zero answers).
3. Explain **implicit selection**, **crossover between matching gene slots**
   and **mutation**, and read evolution from logs: allele frequencies and
   lineages.
4. Design a **controlled experiment**: null models (random brain), controls
   (shuffled genomes, random founders, no mutation), several seeds, a
   pass/fail criterion fixed in advance.
5. Extend the system: a sense, an action, a mutation instruction or a brain
   ([08 §8](08-code-and-config-reference.md#8-extending-the-system)).

## 4. Running Lab 1

Setup: [07 §2](07-setup-and-usage.md#2-install). Then, from `prototype/`:

```bash
python -m experiments.smoke_run                              # rule-based brain, 5 000 ticks, ≈ 12 s
python -m experiments.smoke_run --backend random             # null model
python -m experiments.smoke_run --backend llm --ticks 500    # the LLM brain, ≈ 7 min on a 16 GB GPU
```

Each run writes `results/runs/smoke/` (change it with `--out`): events,
statistics every 100 ticks, every allele and its lineage, the final population
and a summary ([03 §12](03-world-and-simulation.md#12-what-a-run-writes-to-disk)).

## 5. Suggested activities

Ordered from first contact to open-ended work. A–D need only the rule-based
brain and a laptop; the LLM brain makes them real.

### A. Meet the ecology

- **Goal:** understand what keeps a population alive.
- **Do:** run the rule-based brain and read `stats.csv` and `summary.json`.
  Then change one parameter at a time with `load_config(..., overrides=...)`
  ([08 §2](08-code-and-config-reference.md#2-package-promptevo)): food
  regrowth, the number of predators, the energy cost of moving.
- **Look for:** population size, deaths by cause, lifespan, generations. When
  does the population hit the cap? When does it need newcomers?

### B. Does the brain matter?

- **Goal:** separate the effect of behaviour from the effect of the world.
- **Do:** the same world and seed with `--backend random`, `rule_based` and
  `llm` (short run).
- **Look for:** a random population can't sustain itself (floor + about 250
  newcomers per 5 000 ticks). In the first LLM run, the LLM-read founders
  attacked 16 % of the time and fell to the floor in 400 ticks, while the
  keyword brain kept 17 animals
  ([05 §6](05-decision-backends.md#6-what-the-llm-brain-costs)). Why might an
  LLM read "Never fight." and still attack?

### C. Read and write genes

- **Goal:** see how text becomes behaviour, and how LLMs and keyword rules read
  text differently.
- **Do:** write a genome and ask a brain directly:

```python
from promptevo.backends.base import Query
from promptevo.backends.factory import make_backend
from promptevo.config import load_config
from promptevo.genome import ACTIONS, AlleleRegistry
from promptevo.perception import Observation

cfg = load_config("small")
reg = AlleleRegistry()
genes = {"eat": "Eat whenever food is close.", "flee": "Always run away, whatever happens.",
         "follow": "Stay close to other animals.", "wander": "Keep moving to new places.",
         "rest": "Rest when you are tired.", "mate": "Look for a partner when energy is high.",
         "attack": "Never fight.", "risk": "Cautious: safety comes before food.",
         "social": "Social: feels safer in a group.", "place": "Prefers staying near water."}
g = reg.make_genome(genes)
situation = Observation(energy="low", food="near", predator="near", animal="none")
for name in ("rule_based", "llm"):
    p = make_backend(name, cfg).decide([Query(reg.genome_key(g), reg.genes(g), situation)])[0]
    print(name, {a: round(float(x), 2) for a, x in zip(ACTIONS, p)})
```

  Real output (2026-10-01):

```text
rule_based {'eat': 0.14, 'flee': 0.85, 'follow': 0.0, 'wander': 0.0, 'rest': 0.0, 'mate': 0.0, 'attack': 0.0}
llm {'eat': 0.43, 'flee': 0.48, 'follow': 0.05, 'wander': 0.02, 'rest': 0.01, 'mate': 0.0, 'attack': 0.0}
```

- **Look for:** change one gene ("Always…" → "Never…") and measure the shift
  in its action (a directed test). Find a sentence that a person understands
  but the keyword brain ignores, and one the LLM over-interprets. Always build
  the query key with `reg.genome_key(g)`: the LLM cache uses it, so a
  hand-made key reused for different genes would return stale answers.

### D. Watch evolution

- **Goal:** see selection rewrite text.
- **Do:** run a long simulation (rule-based for speed, or the LLM brain) and
  read it with `python -m experiments.gene_report results/runs/<run>`
  ([10](10-natural-selection-runs.md) explains the report and shows results): the
  fitness of every gene, its frequency at the start, peak and end, and where
  mutant genes came from. Then **write what it doesn't do yet**: allele
  frequency curves per locus (genomes come with the `founder`, `immigrant` and
  `birth` events, and `death` events say by id when each animal leaves),
  diversity over time, and which mutation instructions produced the genes that
  spread (the `operator` field, `llm#<n>`).
- **Look for:** which founder alleles win, which are lost, whether any mutant
  reaches a high frequency, and whether different seeds end differently from
  the same founders.

### E. Mutation

- **Goal:** understand blind variation: mutation doesn't know what helps,
  selection decides what stays.
- **Do:** read `results/mutation_test.md` ([04 §5](04-genome-and-evolution.md#5-mutation)):
  every founder sentence mutated at four temperatures, and genes mutated 30
  times in a row without selection. Then change `prompts/mutate_v2.txt` (add,
  remove or reword instructions) or `evolution.temperature`, rerun
  `python -m experiments.mutation_test --temps 1.2 --tag mine`, and compare.
  Measure per-locus diversity (`metrics.shannon_diversity`) and mean gene
  length over a run, with and without mutation (`smoke_run --no-mutation`).
- **Look for:** which instructions make big jumps; whether genes get longer,
  stranger or more alike after many mutations; whether any mutant spreads.

### F. Observation wording

- **Goal:** prompts are part of the system.
- **Do:** switch `backend.obs_style` from V1 ("Energy: low. Food: near.") to
  V2 ("I am hungry and weak. Food is close.") and rerun the gate or a short
  LLM run.
- **Look for:** do the same genes produce different behaviour when only the
  wording of the situation changes?

### G. Controls and the scientific method

- **Goal:** tell selection apart from drift and luck.
- **Do:** predict, then run (rule-based brain, several seeds):
  `shuffled: true` (genes inherited but not expressed), `random_founders:
  true`, `p_mut: 0`, `sexual: false`
  ([04 §7](04-genome-and-evolution.md#7-experimental-controls)).
- **Look for:** which differences are larger than the spread between seeds?

### H. Open problem: does random text matter? (advanced)

- **Goal:** take part in the open research question of the project.
- **Do:** run the gate ([07 §4](07-setup-and-usage.md#4-check-a-new-model)) and
  try to fix G2: the prompt, the all-zero answers, cleaner control sentences
  ([06 §6](06-experiments-and-results.md#6-known-issues-and-open-questions)).
- **Look for:** MI_G for founder genes clearly above MI_G for random text,
  without losing directed accuracy.

## 6. Compute budget

| Brain | Cost on the measured machine (RTX 5080 16 GB) | Suitable for |
|---|---|---|
| random, rule-based | ≈ 12 s per 5 000 ticks on a CPU | any laptop, any activity |
| LLM, gemma4:12b | ≈ 7 min per 500 ticks (small profile); ≈ 1 h per 5 000 ticks | short runs in class; long runs as background jobs or on a lab server |

The cache makes repeated questions free. A class running the same founders in
the same world shares many answers if it shares a cache, for example on a lab
server. Without GPUs for students, the options are a shared Ollama server, an
Ollama Cloud plan, or the rule-based brain for most activities
([05 §5](05-decision-backends.md#5-choosing-the-model)).

## 7. Toward the next labs: terrain and foliage

In the next labs, students build terrain and then foliage. Those become the
animals' world:

| Lab | What changes for the animals | Where it plugs into the code |
|---|---|---|
| Terrain | impassable water and steep ground, maybe slower movement uphill; food that depends on place | world generation (`World._make_terrain`), walkability (`World.walkable`), movement (`step_toward`, `step_heading`), keys under `world:` |
| Foliage | vegetation as food sources with their own regrowth, cover from predators | food regrowth (`World.regrow_p`, `regrow_food`), perception (`perception.sense`) |

A preview exists today: `--world terrain_preview` adds noise-based water and
mountains, with food regrowing twice as fast near water. Questions to carry
from Lab 1:

- **Re-adaptation:** do founders that evolved on the flat world do better or
  worse on terrain than fresh founders?
- **Place genes:** "Prefers staying near water." means nothing on the flat
  world. Does it spread once food grows faster near water?
- **New senses:** a terrain lab may add an observation such as "Ahead: water"
  (a new field in `Observation`, a new phrase in the text), and with it new
  genes.

The requirements for the world are listed in
`Docs/redesign/06-world-terrain-foliage.md`, which still needs the details of
the terrain and foliage labs from the course owner.
