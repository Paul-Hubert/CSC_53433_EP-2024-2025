Testing

EvoSim's tests build small worlds in code, put animals exactly where a rule needs them, run a few ticks and check what happened. No test calls a language model: a scripted brain and fake mutators and servers answer instead, so every test repeats exactly with its seed. This page explains the test assemblies and the toolkit they share, EvoSim.Testing. To test a module of your own step by step, and to see what the conformance suites check, read Testing your module.

The test assemblies

Every test states what it checks in its Description, with the test id and the rules it keeps: [Test, Description("T-ACT-04 (ACT-10): …")]. The coverage gate (Core/CoverageTests.cs) fails when a MUST rule of the specification is cited by no test.

WorldFixture and New

Derive your test class from WorldFixture and start each world with New(seed = 1234, waitMode = Freeze, name = "Test World"). It returns an empty WorldBuilder: a root with a World and its Environment, Brains and Phases objects, kept inactive until you build it. After each test the fixture destroys every world it made. Give each world of one test its own name when a test builds several. The default wait mode, Freeze, delivers late answers at once (WaitMode).

Building a world

Each call adds one thing and returns the builder, so the calls chain. A world has only what you add: no phase runs unless you add it, and species start with no founders.

WorldBuilder call Adds
Flat(width, depth) a FlatGround, x from 0 to width and z from 0 to depth, in meters
Ground<T>(width, depth) a flat ground of your subclass: PondGround, RampGround, DoubleDistanceGround
Food(initial, regrow, name, energy, hungryCover) a FoodGrid named "Grass" with an Edible (25 points an item); Food(0f, 0f) is empty and never regrows
Cover(fraction), Carcasses() a CoverLayer "Thickets" (share 0.2), the CarcassSystem
Service<T>(name, configure) any WorldService: brains, mutators and caches go under Brains, the rest under Environment
DefaultBrain<T>(configure) a brain under Brains, made the World's default
Phase<T>(configure) a phase after those added so far; phases run in that order (TICK-01)
Species(name, s => …, id) a species, whose modules s (a SpeciesSetup) adds
Configure(w => …) any World setting now: w.TextStyle, w.TickLimit, w.Asexual, w.DecisionPeriod…
Get<T>(), Root, World the first component of a type built so far; the root GameObject; the World
SpeciesSetup call Adds
Population(n) n founders at random walkable positions when the world initialises (POP-04)
Action<T>(name, configure, founders, withGene) an action under Actions with a TextGene on the same object; the name defaults to the class name without "Action", in lower case
Sense<T>(configure, name) a sense under Senses; the call order is the order of the situation text (SPEC-03)
Module<T>(configure, name) any other species module under Life: a stat, a rule, a locomotion, a crossover…
On<T>(configure) a component on the species' own object: an Edible, a SearchRule, a Body
Get<T>(), Find<T>(gameObjectName) a module added so far, to wire one module to another

Every configure argument is called at once with the new component: set its fields there, or keep a reference to it.

The Lab recipes

Lab adds the reference parts in one call each, with the prototype's values. They are extension methods, so they chain with the builder's own calls.

Call Adds

PreySenses(), PredatorSenses() the 7 and 6 reference senses, in situation-text order
PreyActionSet(), PredatorActionSet() the 6 and 4 actions, each with its text gene, founder pool and contrast pair
LifeRules(cap, floor, incubation) litters of 2 to 4, uniform crossover, incubation, a cap and a floor
LlmMutation(rate) the LLM mutation with the reference deck v4; the world then needs a mutator
ReferencePhases(order) the 11 reference phases in the order of TICK-04
FakeMutation(configure) a MutatorService whose client is a FakeMutator
Recorder(files), CheckInvariants() a run recorder (no files unless files is true); an InvariantPhase
Ecology(size, cover, food, prey, predator, regrow) a 48 m square with grass, cover, carcasses, eggs and both species, without founders, phases or brain
Lab1(prey, predators, …) the Lab 1 small world (S03): 24 prey, 4 predators, caps and floors, the phases, the fake mutator, the random brain

Build or BuildUninitialized

Build activates the tree and calls Initialize: discovery, validation, founders. It returns the ready World, or throws with the validation report. To test validation itself, call BuildUninitialized and validate yourself:

var w = New(name: "requires").Flat(20, 20).DefaultBrain<RandomBrain>()
    .Species("prey", s => s.Action<RestAction>("rest").Module<KinematicLocomotion>(name: "Locomotion").Module<NeedsEnergyProbe>())
    .BuildUninitialized();
var report = new ValidationReport();
Assert.IsTrue(w.Prepare(report), report.ToString());
Assert.AreEqual("Add Energy", report.Messages.Single(x => x.Id == "V-26").Fix.Label);

Placing and steering animals

After Build, Place sets up the exact situation a test needs. It records no event.

Call Does
Place.At(x, z) a point on the ground plane
Place.Animal(species, point, genome, heading) an animal with each gene's first founder allele (or the given genome), its height set from the ground; the species' modules hear OnBorn
Place.WithGenes(species, point, "sentence", …) an animal whose text genes hold these sentences, locus by locus
Place.Food(layer, point), Place.Cover(cover, point) an item, or cover, on the cell that holds the point
Place.Carcass(carcasses, species, point, killerId, portions, energy, lifetime) a carcass, as if an animal had been killed there

A placed animal has chosen no action. a.Choose("eat") sets it by name, a.SetStat("energy", 90f) and a.StatOf("energy") write and read a stat by name, and a.Age = 200 makes it an adult. With only .Phase<ActPhase>() the chosen action runs every tick; with the decision phases and a brain, the brain chooses again at the next decision. Advance(n) then runs n ticks.

The scripted brain

ScriptedBrain answers each query in this order:

  1. FailWhen(query) returns a message: the query fails, as if the server were down (DEC-34);
  2. Vectors["species|observation key"] holds a row: that row;
  3. Policy(query) returns a row: that row;
  4. otherwise: a uniform row.

ScriptedBrain.Prefer(species, "flee", epsilon) makes a row that prefers one action, and ScriptedBrain.Token(query, "Predator") reads one sense's token, so a policy can react to the situation. The brain counts Calls and Batches, keeps every query in Seen, and answers DelayCalls Advance calls late. MixesSpecies, ActionLimit, TokenLimit and TakesAttachments play the limits of real brains. The system ships no rule-based brain: this one is for tests only.

Fake mutators and servers

FakeMutator replaces the mutator model. By default it answers each sentence with "quickly" added before its period; set Answer = (sentence, seed, prompt) => … for another rule, FailWhen to fail, DelayCalls to answer late. It records Prompts and BatchSizes. The operators, guards and redraws stay the real ones: an answer equal to its parent is rejected and drawn again (MUT-13).

FakeHttpTransport plays a server for an HTTP brain or mutator client: set it as their Transport. Jev() and OllamaPoints() answer like the two reference servers, Respond scripts any answer, FailWith returns an HTTP status, Hang never answers, DelayMs waits. Requests and MaxInFlight show what was sent. See An HTTP brain or mutator server.

Checks

  • Golden files (Golden). Golden.Check("situations.tsv", text) compares a long output with a file in Assets/EvoSim/Tests/Golden; a missing file is written from this run. See Golden files.
  • Invariants (Invariants). Invariants.Check(w) lists every broken invariant of 30 §5 (positions, NaN, stat ranges, ids, dead animals still listed, probability rows, cap and floor, carcass portions, genomes). CheckInvariants() adds an InvariantPhase that fails the test at the first one; call it after the other phases.
  • Statistics (Stat). Stat.Binomial(successes, trials, p) and Stat.Mean(values, expected) pass within 4 standard errors; Stat.Uniform(counts) is a χ² test. Draw from a fixed seed, so the test passes or fails the same way every run.
  • Static checks (SourceScan). SourceScan.Find(SourceScan.Files("Runtime"), pattern) searches the code with comments removed. Core/StaticChecks.cs uses it to forbid UnityEngine.Random (T-RAND-01), Actions/ActionTests.cs to forbid actions that read genes (T-ACT-09).

A complete test

Two adults next to each other, a brain that always chooses mate, one tick: the babies are born during the tick and aged by its death phase, so they end it at age 1 (ANIM-35).

using System.Linq;
using EvoSim;
using EvoSim.Testing;
using NUnit.Framework;

public class BabyAgeTests : WorldFixture
{
    [Test, Description("ANIM-35: babies born in a tick are aged by that tick's death phase")]
    public void BabiesAgeOnTheirBirthTick()
    {
        var w = New(name: "baby age").Ecology(40f, 0f, 0f, regrow: 0f, prey: s => s.LifeRules(40, 0)).ReferencePhases()
            .DefaultBrain<ScriptedBrain>(b => b.Policy = q => ScriptedBrain.Prefer(q.Species, "mate")).Build();
        var prey = w.FindSpecies("prey");
        foreach (var x in new[] { 10f, 10.5f })
        {
            var a = Place.Animal(prey, Place.At(x, 10));
            a.Age = 200; a.SetStat("energy", 90f);
        }
        w.Advance(1);
        var babies = prey.Animals.Where(a => a.Origin == "birth").ToList();
        Assert.IsNotEmpty(babies);
        Assert.IsTrue(babies.All(b => b.Age == 1 && b.BornTick == 0));
    }
}
