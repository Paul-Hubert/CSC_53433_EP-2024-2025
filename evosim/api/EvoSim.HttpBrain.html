Examples

The heart of OllamaPointsBrain: one chat call per request, the points turned into a row.

public class OllamaPointsBrain : HttpBrain
{
    public override string Id => "ollama-points";
    public override string Mode => "points";
    public override string AnswerInstruction => Instruction;
    protected override string HealthPath => "/api/tags";

    protected override async Task AnswerAsync(HttpCaller c, IReadOnlyList<BrainRequest> requests, BrainAnswer answer)
    {
        var calls = new List<Task>(requests.Count);
        foreach (var r in requests) calls.Add(One(c, r, answer));
        await Task.WhenAll(calls).ConfigureAwait(false);
    }

    async Task One(HttpCaller c, BrainRequest r, BrainAnswer answer)
    {
        try
        {
            var response = await c.PostAsync("/api/chat", Body(r.Text, r.Actions)).ConfigureAwait(false);
            var row = PointsAnswer.ToRow((string)response["message"]?["content"], r.Actions, out var problem);
            if (row == null) answer.Fail(r.Index, problem);
            else answer.SetRow(r.Index, row);
        }
        catch (Exception e)
        {
            answer.Fail(r.Index, e.Message);
        }
    }
}

Remarks

The Ask brains phase calls Ask(IReadOnlyList<DecisionQuery>) on the main thread with the queries that the memo and the answer cache could not answer (DEC-30, DEC-33). Ask(IReadOnlyList<DecisionQuery>) builds one BrainRequest per query, with the text from TextFor(DecisionQuery), returns an unfinished answer at once and runs AnswerAsync(HttpCaller, IReadOnlyList<BrainRequest>, BrainAnswer) on the thread pool. Every await uses ConfigureAwait(false), so the answers never need the main thread: the Freeze wait mode can block it, and the Responsive mode keeps the editor drawing (SPACE-14). When AnswerAsync(HttpCaller, IReadOnlyList<BrainRequest>, BrainAnswer) ends, or throws, every request left without a row fails and the answer is completed.

Caller applies the time-out of each try, the tries with doubling waits and the cap on requests in flight (DEC-42). A request that still fails becomes a failed row. A strict brain (the default for HTTP brains) then stops the run cleanly; a non-strict one gets a uniform row, counted and never cached (DEC-40, DEC-34). The answers are stored in the answer cache by the decision phases, not here (DEC-33).

To call another server, derive from it: implement AnswerAsync(HttpCaller, IReadOnlyList<BrainRequest>, BrainAnswer) (post each body with PostAsync(string, JObject, CancellationToken), read the answer, then call SetRow(int, float[]) or Fail(int, string) for every request) and HealthPath, and override Id. Override ModelIdentity and Mode too, so that cache keys change with the model. AnswerAsync(HttpCaller, IReadOnlyList<BrainRequest>, BrainAnswer) runs on another thread: it must not touch a Unity object. Place the component under the World, like any brain. An API key never goes in a field: apiKeyVariable names the environment variable that holds it (OUT-04).

Remarks

Runs on the thread pool: use no Unity API here, and await with ConfigureAwait(false). Don't call Complete(): the base does it when this task ends. An exception thrown here fails every request still without a row, with its message.

Ask(IReadOnlyList<DecisionQuery>)

Builds one request per query on the main thread, starts sending them on the thread pool and returns at once an answer that fills later (DEC-11). It counts one model call per query.

public override BrainAnswer Ask(IReadOnlyList<DecisionQuery> batch)

Parameters

batch IReadOnlyList<DecisionQuery>

The queries the memo and the cache could not answer, at most one per memo key (DEC-32); never empty.

Returns

BrainAnswer

One row or one failure per query, in query order: Now(float[][]) when every row is ready, or Later(int) filled from another thread, then completed.

Remarks

Called on the main thread by the ask-brains phase, once per tick and per batch. Read only the queries: a row must depend on the query alone (DEC-12), and the brain must not change the world (CORE-06). A query it can't answer is marked with Fail(int, string), never answered with a made-up row.
