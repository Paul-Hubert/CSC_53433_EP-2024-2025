Examples

// A kind of one's own (from EvoSim's test probes): nothing moves or rots unless given a lifetime.
public class Fruit : Entity
{
    public override string Kind => "fruit";
}

public class FruitSystem : EntitySystem<Fruit>
{
    public override string Kind => "fruit";
}

// From a phase: a fruit falls at p and rots in 50 ticks.
World.Service<FruitSystem>().Add(new Fruit { Position = p, LifetimeLeft = 50 });

Remarks

Derive from it with your entity type, give the kind a name (Kind), and place the component under the World (reference: under Environment). Entities enter through Add(T); actions and senses find them with Nearest(Vector3, float, Animal, Func<T, Animal, bool>, out T, out float) or NearestEntity<T>(Animal, float, Func<T, Animal, bool>). Once per tick the environment phase calls UpdateEntities(TickContext): Move(T, TickContext) each one, count lifetimes down, then remove the used-up and expired ones, calling OnRemoved(T, string, TickContext) for each.

The list stays in creation (id) order, so every loop over it is deterministic (RAND-05). An override of Move(T, TickContext) draws random numbers only from a named stream of t.

Put an Edible on the same GameObject to make the kind food; diets then name it "<kind>:<species>" (22 §15).

The nearest entity within radius that passes the filter (SPACE-07); ties by id (SPACE-08). The filter receives the viewer, so it needs no closure.

UpdateEntities(TickContext)

Moves, ages and removes entities; the environment phase calls it once per tick (ENV-22).

An entity whose lifetime reaches 0 here is removed in the same call ("expired"), as is a used-up one ("used up"). The others keep their order.
