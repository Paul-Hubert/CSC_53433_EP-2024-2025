Examples

Running a World from code, as a test or a batch run does:

world.Seed = 7;
world.WaitMode = WaitMode.Freeze;
if (!world.Initialize()) { Debug.LogError(world.LastReport); return; }
world.Advance(500);
world.Stop("done");
Debug.Log(world.Events.ShortHash);

A module finds what it needs from its World in Initialize (ARCH-08):

public override void Initialize() => food = World.Service<FoodGrid>("Grass");

Remarks

Place one World at the root of a simulation. Everything below it belongs to it (ARCH-05): the species, the tick phases and the services. A World inside another World is an error (V-16). Modules never set themselves up in Awake, Start or OnEnable: the World calls them, always in the same order (ARCH-04).

Initialize() (called by Play(), or in Awake when StartOnPlay is on) first runs Prepare(ValidationReport): random streams and event log from the seed, species found, world modules found and bound, services initialised (the ground first), each species' modules collected, genes bound, every Declare(SpeciesBuilder) then every Initialize(), phases initialised, founder pools registered, the food web derived, signatures and prompts built, then validation. When no error was found it makes the views, calls every Begin(), and spawns the founders (POP-04).

A tick runs the phases in order (TICK-01). Before each phase the World asks its WaitsFor(TickContext); when the answer is not ready, Responsive returns from Advance(int) and resumes the same phase on a later call, and Freeze blocks on Wait(). Both give the same events hash (RAND-11). Stop conditions are checked only between ticks, so a stopped run's files are complete (RAND-20).

The class is split in several files: World.Animals.cs (founders, newcomers, distance), World.Deaths.cs, World.FoodWeb.cs, World.Species.cs (species added during a run), World.Space.cs, World.Views.cs and World.Checks.cs.

Advance(int)

Runs up to maxTicks ticks and returns how many completed. In Responsive mode it returns early when a phase must wait, and the same tick continues at that phase on a later call; in Freeze mode it blocks.

public int Advance(int maxTicks)

Parameters

maxTicks int

The most ticks to run in this call.

Returns

int

The ticks completed in this call: fewer than maxTicks when a phase waits (Responsive), when the run stops, or 0 once it stopped.

Remarks

Before running a phase it asks the phase's WaitsFor(TickContext). A Pending that is not done counts once in WaitCount; then Responsive returns, and Freeze calls Wait(). Stop conditions are checked between ticks only (RAND-20).

An exception in a phase stops the run (its reason names the phase) and is thrown again.

Exceptions

InvalidOperationException

The World is not initialised.

RecordDeath(Animal, string)

Marks the animal gone and records its death once (ANIM-42): cause, age, generation, meals, offspring, and the killer for a kill. It leaves the species' list at the end of the phase.

public void RecordDeath(Animal a, string cause)

Parameters

a Animal

The animal that dies; nothing happens when it is already gone.

cause string

The cause, as events and the statistics name it: "killed", "starvation", "old_age", "migrated", or a cause of your own (it gets its deaths_<cause> column).

Examples

World.RecordDeath(a, "lightning");   // a death of your own, in your own phase

Remarks

After the death event, it calls the species' OnDied(Animal, string), then each of its modules' OnDied(Animal, string), then each world module's OnDied(Animal, string).

The animal stays in Animals until the phase that killed it calls RemoveGone(): a death phase of your own must call it too.
