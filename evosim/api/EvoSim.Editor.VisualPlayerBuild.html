Class VisualPlayerBuild

Namespace
EvoSim.Editor
Assembly
EvoSim.Editor.dll

Builds a Windows player that draws a run (07 real-time test): Windows 64-bit, Mono, the reference scenes (HideVsFlee first) given here, not in the Build Settings, into Builds/EvoSim/<date>/EvoSim.exe. Project and Player settings are left as they are. Batch: -executeMethod EvoSim.Editor.VisualPlayerBuild.BuildFromCommandLine [-scenes HideVsFlee,Lab1_Full] [-out folder]. Run it: EvoSim.exe -scene HideVsFlee -seed 1234 -ticks 600 -speed 5 -brain JEV -capture 10 -quitAtEnd -screen-fullscreen 0 -logFile player.log (PlayerArgs).

Remarks

From the menu: EvoSim ▸ Build ▸ Visual Player (a dialog shows the result). Batch, editor closed: Unity.exe -batchmode -nographics -projectPath . -executeMethod EvoSim.Editor.VisualPlayerBuild.BuildFromCommandLine [-scenes HideVsFlee,Lab1_Full] [-out Builds/EvoSim/2026-10-11]. From the open editor with the unity CLI: BuildLater(string, string), or CompilePlayerScriptsLater() to check that the player scripts compile.

The Standalone scripting backend must be Mono: the build refuses otherwise rather than change Player settings (RAND-12 compares Mono runs). The player writes its run files and captures next to the exe, under Logs/EvoSim/, and keeps its answer cache in Library/EvoSim/AnswerCache.

Unity.exe -batchmode -nographics -projectPath . -executeMethod EvoSim.Editor.VisualPlayerBuild.BuildFromCommandLine [-scenes A,B] [-out folder]: -scenes lists scene names of ScenesFolder (default DefaultScenes), -out the output folder (default DefaultFolder()).
