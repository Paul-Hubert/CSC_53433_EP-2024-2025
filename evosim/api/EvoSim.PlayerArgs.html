A watched run's settings from a command line (the Windows player): -scene name, -seed n, -ticks n, -minutes m (wall clock), -speed (ticks per second | fast | fixed), -wait (responsive | freeze), -brain (a brain's GameObject name or id), -capture seconds (0 = start and end only, off = none), -cache folder, -run folder name, -noMutation, -quitAtEnd, -window WIDTHxHEIGHT (a window of that many pixels), -stagger (every species decides staggered, DEC-04). Parsing and applying are separate, so tests check both without a player.

Remarks

The arguments (names in any case; an argument left out keeps the scene's setting):

  • -scene NAME: the scene to run, by name; a World of another scene doesn't start, and NAME loads instead.
  • -seed N: the run seed, a whole number, 0 or more (Seed).
  • -ticks N: stop after N ticks; 0 = no limit (TickLimit).
  • -minutes M: stop after M minutes of wall-clock time, more than 0 (WallClockMinutes).
  • -speed S: S ticks per second, at least 0.1 (real time); fast: as many ticks per frame as fit in the time budget; fixed: a fixed number of ticks per FixedUpdate (RunSpeed). Results never depend on it (SPACE-11).
  • -wait MODE: responsive or freeze, how a tick waits for the brains (SPACE-14).
  • -brain NAME: the World's default brain, by GameObject name or brain id; a species with a brain of its own keeps it, and is reported.
  • -capture S: seconds of real time between screen captures; 0 = only at the start and the end; off = no capture (RunCapture).
  • -cache FOLDER: the answer cache's folder, relative to the build's folder (AnswerCache).
  • -run NAME: the run folder's name for every RunRecorder; {world} and {seed} are replaced.
  • -noMutation: no mutation at all (the NO-MUT control, NoMutation).
  • -stagger: every species decides staggered (DEC-04); a DecisionSchedule is added where a species has none.
  • -quitAtEnd: quit the player once the run stopped and its captures are written.
  • -window WxH: a window of W × H pixels, at least 160 × 120, instead of the player's own screen mode.

Other arguments (Unity's own, such as -logFile) are ignored. A value that doesn't parse is listed in Problems, and that setting keeps the scene's value. Example: EvoSim.exe -scene HideVsFlee -seed 1234 -ticks 600 -speed 20 -capture 10 -run NAME -window 1920x1080 -quitAtEnd.

Remarks

Called by PlayerLauncher from Configuring. Only given arguments change the World; a brain, cache or species problem is added to Problems. -scene, -capture, -window and -quitAtEnd are handled by the launcher.
