TickContext class What a phase gets each tick: the world, the tick number and the named streams.
TickPhase abstract class One step of a tick.
TraitId struct A handle to a declared trait (ANIM-15): a per-animal number fixed at birth, with a default and a range.
Units static class Units of the simulation: meters on the horizontal plane, ticks for time (README, Units).

ValidationMessage class One problem, naming the object at fault (EDIT-02).

WaitMode enum How a tick waits for brain answers and mutations (SPACE-14).

WorldQueries class The queries senses and actions share (ACT-05, SENSE-06): within the animal's vision, never itself, never a killed animal, never an animal hidden from it in cover, diets checked. Ties by id (SPACE-08).

Tick phases

Assets/EvoSim/Runtime/Phases

Type Summary
ActOrder enum The order in which animals act within a tick (ACT-30).
ActPhase class Every living animal acts, in the act order (ACT-30): its action plans an intent and an interaction, its species' locomotion moves it, interactions apply within reach, then its metabolism is paid and busy counters drop (TICK-04 #4, ANIM-20, ANIM-30).
AskBrainsPhase class Builds each deciding animal's query (DEC-10), answers it from the memo (DEC-30) or the answer cache (DEC-33), sends the rest as one batch per brain — per species for brains that can't mix species — with identical keys sent once (DEC-13, DEC-15, DEC-32).
BreedPhase class After all animals acted (TICK-06): each ready animal that chose mate and hasn't bred this period breeds with the nearest ready partner within reach that hasn't bred either — one partner's choice is enough (REPRO-02, REPRO-03). A litter is conceived (REPRO-10, REPRO-11): one egg per baby with its own crossover and its mutations drawn now (GENE-32, MUT-30); the LLM mutations are sent as one batch at the end (MUT-31).
ChooseActionsPhase class Waits for the brains (TICK-03), stores fresh answers in the memo and the cache (never a failure, DEC-34), and draws each deciding animal's action with its species' sampling stream after the temperature (DEC-20, RAND-03).
DeathPhase class Removes killed animals; every living animal ages by one tick (babies of this tick included); then each species' death rules (starvation, old age…) in module order.
EnvironmentPhase class Resource layers regrow, each with its own stream; entities move, rot or vanish (TICK-04 #9, ENV-03, ENV-22).
FloorPhase class While a species has fewer animals than its floor, a newcomer arrives (POP-03); it decides at the next tick (TICK-05).
HatchPhase class Eggs due this tick hatch, in conception order (REPRO-22), once their genome is complete: the tick waits for the mutator if its answers aren't in (MUT-32, REPRO-24). Each baby starts with the child energy, full stamina, age 0, at its first parent's position (REPRO-12), and a birth event records its litter and mutations (MUT-03).
MigrationPhase class Above its cap, a species loses animals chosen uniformly at random with its migration stream, ignoring genes, stats and position (POP-01, POP-02); animals born this tick are spared unless too few older ones remain.
RecordPhase class A statistics row every statsEvery ticks and the periodic flushes (TICK-04 #11, RAND-22); live statistics for the editor.
SensePhase class Picks who decides (DEC-01): every living, not busy animal on the decision ticks, and animals without an action on the others; rebuilds the spatial index; casts the rays of batched senses in one batch; reads every sense of every deciding animal from the state at the start of the tick (TICK-04 #1, SENSE-04, TICK-05).

Senses

Assets/EvoSim/Runtime/Senses

Type Summary
AgeSense class Young or adult (06 §4): adult from the maturity trait (ANIM-36), reference 150 ticks.
BandedSense abstract class A sense that reports how far the nearest something is, in bands (06 §3): "here" (optional), the bands, "none". Wording (SENSE-10…13): V1 "Food: 1-4 meters away." / V2 "The nearest food is 1-4 meters away.".
Bands class Distance bands (06 §3, SENSE-20): increasing edges e1 < … < ek and a vision v > ek. A distance falls in the first band with d ≤ ei, in "far" if ek < d ≤ v, and is "none" beyond v. Reference: 1, 4, 10 m and 20 m.
BatchedSense abstract class A sense that casts rays (line of sight, terrain ahead): it asks for its rays first; the sense phase casts the rays of all deciding animals in one batch, then each sense reads its results (SENSE-30). It must give the same tokens as evaluating it one animal at a time (SENSE-31).
LevelSense class A stat as low, medium or high (ANIM-12): low < low threshold ≤ medium ≤ high threshold < high. Reference: energy 30 / 70, stamina prey 20 / 40, predators 10 / 20.
NearestAnimalSense class The nearest animal of a set (threats, prey, kin, listed species), in bands (06 §4).
NearestCoverSense class The nearest cover (06 §4): "here" when standing in cover, else the bands or none. Without a cover module it always says none (ENV-12). Reference label "Cover".
NearestEntitySense class The nearest entity this animal may eat (06 §4): a carcass with portions left, not its own kill, not eaten from by it yet; or an egg its diet eats. Reference: the predator's "Carcass" sense.
NearestResourceSense class The nearest item of a layer the species grazes (06 §4): here, the bands, none. Reference label "Food".
Observation class The tuple of an animal's sense tokens at one decision, in sense order (SENSE-02).
ObservationSet class A fixed list of situations, written by sense label and token (15 §2, "the 48 situations"): the prototype's rows ({"energy": "low", "food": "close", "animal": "adjacent", "animal_ready": true, …}) are matched to a species' senses by label; a sense the row doesn't name takes a default token.
ObservationSet.Row class One situation: tokens by sense label, plus its source and tags.
ObservationView class An observation read through its species' senses: the token of a sense by label (CTRL-10).
RayBatch class The rays of all deciding animals of a sense phase, cast in one batch (SENSE-30) with RaycastCommand, or one at a time with Physics.Raycast (Immediate, for comparison: SENSE-31). Version-specific physics code lives here (ARCH-10).
Sense abstract class Reads one animal and the world and returns one token from a fixed list (SENSE-01): what the brain is told about one aspect of the situation, such as the nearest food or the energy level.
SenseContext class What a sense may read at a decision: the world state at the start of the tick (SENSE-04), through the same queries as actions, so hidden and killed animals are never reported (SENSE-06).

Decisions and brains

Assets/EvoSim/Runtime/Brains

Type Summary
AnswerCache class A persistent store of brain and mutator answers (DEC-33, MUT-14): append-only JSON lines, one file per brain, loaded at the first lookup. Keys hash everything that can change an answer, so a repeated run replays without model calls (RAND-21). Rows are stored with round-trip precision, so a replay is bit-identical.
Brain abstract class Maps a batch of queries to probability rows over the species' actions (DEC-11).
BrainAnswer class A brain's answer to a batch (DEC-11): one probability row per query, in query order, or a failure per query. Fast brains fill it at once; HTTP brains later, from another thread, then mark it done.
Decision class One animal deciding this tick: what it sensed, what its brain was asked and answered (08 §1–§5).
DecisionMemo class Within a run, the answer for a key (species, brain, brain-visible genome key, observation) is computed once and reused (DEC-30).
DecisionQuery class What a brain receives for one deciding animal (DEC-10): its species, the genes its brain reads (label and sentence, in locus order), its observation, its situation text in the world's style, and any attachments.
DecisionSchedule class A species' own decision period, and staggering (DEC-04, MAY): an animal decides when (tick + id) % period == 0. Both change behaviour. In the reference scenes every species has one, staggered, with the World's period (owner 2026-10-10); a species without one decides all together, every World period, as the Python prototype does.
DecisionState class The decisions of the current tick, the brain answers they wait for, and the run's memo (08 §1–§4).
PromptTemplate class A species' prompt with three holes: {genes}, {situation}, {ask} (PROMPT-01, PROMPT-04). Its id is a hash of this text, so any change to a header, an action line or a rule changes the id and the cache key (PROMPT-05).
PromptWriter class Collects the action lines and rule lines that modules contribute to a species' prompt (PROMPT-01).
RandomBrain class Uniform over the species' actions, whatever the genes and the situation: the null model (08 §6).
Sampling static class Sampling temperature (DEC-20): p^(1/τ), renormalised; τ < 1 sharpens, τ > 1 flattens. Pure functions.

HTTP brains and the mutator client

Assets/EvoSim/Http

Type Summary
BrainRequest class One decision query as an HTTP brain sends it: its place in the batch, the text for the model and the species' action names. builds it on the main thread; reads it on the thread pool, so it holds plain values only, no Unity object.
HttpBrain abstract class The base of the brains that ask a model server over HTTP (08 §6): it turns a batch of queries into requests, sends them off the main thread and fills the when the answers come back.
HttpCaller class JSON calls to one server with the reference client behaviour (DEC-42): a time-out per try, tries with doubling waits between them, a cap on requests in flight. The API key is read from its environment variable at each call and only sent, never stored or logged (OUT-04).
HttpChecks static class Checks shared by HTTP brains and mutator clients (the key checks, V-61, are ).
HttpFailure class An HTTP call that failed: an error status, or every try used (DEC-40, DEC-42). Messages never hold keys (OUT-04).
HttpMutatorClient abstract class A mutator model behind a server (10 §2): one chat call per request with the prompt alone (CORE-07, MUT-11), the request's seed and temperature, thinking off. Calls run on the thread pool and fill the reply; the MutatorService caches answers and batches rounds (MUT-14, MUT-31).
HttpStats class What a brain's or mutator's HTTP calls did: tries, retries, failures, latencies (B-01, brain health window).
IHttpTransport interface Sends one HTTP request and returns the response body; throws HttpFailure for an error status.
JevBrain class JEV choice (08 §6): a distilled decision model behind vLLM. One /v1/completions request per batch with the list of texts, max_tokens 1, the option letters as the only allowed tokens and their log-probabilities; each row is softmax((log-prob + head bias) / T) with the head and T of the pinned revision. Options always in the species' action order; at most 16 (DEC-14); inputs above the training length are counted, not cut.
JevBrain.SpeciesQuestion class The question asked for one species (the prototype asked predators "Which action does this predator take now?").
JevHead class JEV's decision head and calibration at a pinned revision (08 §6): the option letters' token ids, a bias per slot, the temperature of the "choice" kind. Row = softmax((log-prob + bias) / T) over the options.
OllamaMutatorClient class The reference mutator (10 §2): a model in Ollama on the CPU (gemma4:26b, owner 2026-10-10; num_gpu 0, num_ctx 1 024), thinking off, so the GPU stays JEV's.
OllamaPointsBrain class LLM, points mode (08 §6): one Ollama chat call per distinct query; the prompt ends with the points instruction, the answer is constrained by a JSON schema, temperature 0, a fixed seed, a fixed context length, thinking off; points become a row by DEC-41.
OllamaTags static class Reads a model's digest from Ollama's /api/tags (first 12 characters), for cache keys and run info (DEC-33, GENE-12).
OpenAIMutatorClient class A mutator behind an OpenAI-compatible server (vLLM, docker profile gpu-mutator): /v1/chat/completions with the seed and temperature, thinking off through chat_template_kwargs.
PointsAnswer static class Points answers to rows (DEC-41): a missing action counts 0, negative points count 0, every action gets +0.01, then the row is normalised, so an all-zero answer becomes uniform. An answer that isn't a JSON object, or points that aren't numbers, are failures (as the prototype's int() raised).
RecordingTransport class Wraps a transport and keeps every request body and answer, for integrity checks that inspect what a model received (B-11).
SystemHttpTransport class The real transport: an HttpClient owned by one brain or mutator client (ARCH-07: nothing shared between worlds), every await with ConfigureAwait(false) so answers never need the main thread (the Freeze mode blocks it, SPACE-14). Time-outs come from the caller (DEC-42).

Type Summary
ActContext class What an action may do in one tick (ACT-06): ask questions about what the animal could sense, and say where it wants to go (an intent) and what to do on arrival (an interaction). It can't move or change any animal itself.
ActPlan struct One animal's plan for a tick (): what writes for each animal of its group, and what the act phase then moves and applies.
AnimalAction abstract class A behaviour the brain can choose (ACT-01).
EatAction class Go to the nearest visible food and eat it (07 §4).
FleeAction class Run away from the nearest threat (07 §4).
FollowAction class Walk toward the nearest other animal of the species, stopping at 1 m (07 §4).
HideAction class Go to the nearest cover and stay in it (07 §4, ENV-13).
HuntAction class Chase the nearer of the nearest huntable animal and the nearest carcass it may eat (a carcass wins a tie, being a sure meal); strike the animal or eat from the carcass on arrival (07 §4).
IInteraction interface A custom contact effect (22 §3, drink): applied after moving when the animal is within of the point its action walked or ran to (ACT-10).
Interaction struct The contact an action asks for on arrival (ACT-03, ACT-10): graze an item, strike an animal, eat a carcass portion or an egg, or a custom one. A small value, so planning allocates nothing.
InteractionContext class What a custom interaction may use when it applies: the world, the ground, the actor's streams.
InteractionKind enum The contact effects of 07 §3 (ACT-11), plus custom ones.
InteractionResolver class Applies the interactions of 07 §3 after moving (ACT-10, ACT-11): only within reach, only if the target is edible and the eater's diet lists it (SPEC-13). Hunters strike at most once per tick (ACT-12).
MateAction class Walk to the nearest ready partner in sight, stopping at 1 m (07 §4).
RestAction class Stay still to catch your breath and save energy (07 §4).
SearchRule class The prompt's search rule (PROMPT-01): what an animal does when its action has nothing to act on (ACT-04). Put it on the species' own GameObject so it comes first among the rule lines.

Locomotion

Assets/EvoSim/Runtime/Locomotion

Type Summary
Intent struct What an action wants this tick (ACT-03): a direction (or none: stay), walk or run, and the farthest it should go (to stop at a target). The locomotion decides what actually happens (MOVE-01).
KinematicLocomotion class The reference locomotion (MOVE-04): straight lines, no physics. Moves by the smallest of speed, stamina and the intent's maximum distance; slides along borders and obstacles; if stuck, takes a random sidestep.
Locomotion abstract class How a species moves (MOVE-01): it turns each animal's intent into movement, and whatever it does is the tick's result. Inherit it for terrain, NavMesh or physics movement (MOVE-07). Speeds are traits (MOVE-03).
MoveContext class What a locomotion gets to move animals: the ground, the distance function, the streams, stamina budgets.

Stats, metabolism and death

Assets/EvoSim/Runtime/Stats

Type Summary
DeathRule abstract class A cause of death checked in the death phase (ANIM-40): return the cause's name, or null to live on.
Digestion class After a kill or a carcass portion the eater is busy digesting for round(digestTicks × gain / killGain) ticks: 50 after a kill (+60), 25 after a portion (+30). Grazing never makes an animal busy (05 §5).
Energy class The energy stat (05 §4): founders and newcomers start at 60, the maximum is 100. Gains are clamped (ANIM-22).

Stamina class Stamina: the meters an animal can move before it must stop (05 §4). Each meter moved costs one point; standing still brings it back, which costs some energy until it is full (ANIM-21).
Starvation class Death by starvation: energy ≤ 0 at the death check (ANIM-40).

Mutation

Assets/EvoSim/Runtime/Mutation

Type Summary
GaussianMutation class The reference operator for number genes (MUT-20): v' = clamp(v + N(0, σ)) to the gene's range.
LlmMutation class The reference operator for text genes (10 §2): one instruction drawn from a deck, sent to the mutator with the sentence after one fixed context line, and nothing else (CORE-07, MUT-11). Every try's instruction and seed are drawn now (MUT-30); rejected answers are drawn again, up to tries (MUT-13).
MutationJob class One mutation of one gene of one baby (10 §1): its choices are drawn at conception (MUT-30); the result may come later, from the mutator (MUT-32). Succeeded → a new value; failed → the inherited allele stays (MUT-04).
MutationOperator abstract class A rule that changes one allele, blind to everything but the gene and the allele (CORE-07, 10 §1).
MutationStats class Mutation statistics of a run (MUT-05): attempts, successes, model calls, rejections by reason.
MutationText static class The LLM mutation's prompt, cleaning and guards (MUT-10…12), as the prototype does them (prototype/promptevo/evolution/mutation.py).
MutatorClient abstract class Sends prompts to the mutator model: Ollama or an OpenAI-compatible server in EvoSim.Http, a fake in tests. It never sees anything but the prompts (CORE-07).
MutatorReply class The answers to a batch of mutator requests, filled later: an answer or an error per request.
MutatorRequest struct One prompt for the mutator model, with its seed and temperature (MUT-11, MUT-14).
MutatorService class Runs LLM mutations (10 §2, §4): every try's instruction and seed are drawn at conception (MUT-30); requests are batched by round — all first tries together, then the redraws of the rejected ones (MUT-31); answers are cached by model, prompt, seed and temperature (MUT-14). It advances only when pumped on the main thread, so the Freeze and Responsive wait modes give the same results.

Environment: food, cover, entities

Assets/EvoSim/Runtime/Environment

Type Summary
Carcass class What a kill leaves (03 §3): a few portions that other eaters may eat, one portion each, never the killer. It rots away when its lifetime runs out, eaten or not, and goes as soon as its last portion is eaten (ENV-22).
CarcassSystem class Carcasses, as each species' edible component describes them: portions, energy, lifetime (03 §3). A carcass of a species is edible when that species' Edible leaves one; diets name it "carcass:<species>".
CellGrid class A grid of square cells over the world rectangle, used inside layers (food cells, cover cells) — never to place animals (02 intro).
Cover abstract class Places where an animal is hidden from the species that hunt it (03 §2).
CoverLayer class Cover in clustered patches (thickets): the top of walkable cells of a value-noise map, drawn from the world stream (03 §2 reference: 20 %, octaves 8 and 4 m).
EatMethod enum How something edible is eaten (SPEC-10).
Edible class Makes what it sits on edible (SPEC-10): a species' animals, a resource layer's items, an entity kind. Without it nothing can eat that thing, whatever the diets say (ENV-23).
Entity abstract class A world object with a position that is not an animal: a carcass, an egg, a water hole (ENV-20).
EntityKind abstract class A kind of entity and its system (ENV-20): carcasses, eggs. Diets name it "<kind>:<species>".
EntitySystem<T> abstract class The entities of one kind, found through spatial queries like animals (ENV-20).
FoodGrid class The Lab 1 food layer (03 §1): at most one item per cell, at the cell centre; a share of walkable cells starts with an item; empty cells regrow at random, uniformly; no food in cover ("hungry cover", ENV-04).
ResourceItem struct One item of a resource layer found by a query: its layer, cell, position and distance (ENV-01).
ResourceLayer abstract class Edible items spread over the ground, e.g. grass (03 §1).
ValueNoise class Value noise on a lattice: random values at lattice points, smoothly interpolated (the prototype's cover and terrain maps). A noise map is built once from a stream; sampling it is a pure function.
