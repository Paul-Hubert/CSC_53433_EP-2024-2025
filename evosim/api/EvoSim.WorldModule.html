Examples

A service that counts births and reports them when the run ends:

public class BirthCounter : WorldService
{
    public int Born { get; private set; }
    public override void Initialize() => Born = 0;
    public override void OnBorn(Animal a) => Born++;
    public override void OnRunStopped(string reason) => Debug.Log($"{Born} births ({reason})");
}

Remarks

Do not derive from it directly: derive from TickPhase for a step of every tick, or from WorldService for something phases and modules use. Place the component on a GameObject under the World and outside every species (one under a species is ignored, V-15). A disabled component or an inactive GameObject is absent (ARCH-06).

The World calls the hooks in this order, and in hierarchy order among modules:

  • Initialize(): services first (the ground before the others), before the species' modules exist; phases later, after every species module is initialised (20 §4).
  • Validate(ValidationReport): after every Initialize, in the editor and at the start of a run; again when a species is added during the run.
  • Begin(): once, when the run starts, before the founders.
  • OnBorn(Animal), OnDied(Animal, string), OnSpeciesAdded(Species): during the run, founders included.
  • OnRunStopped(string): once, at the end.

Never set things up in Awake, Start or OnEnable: Unity doesn't guarantee their order (ARCH-04). Keep no static state (ARCH-07): several Worlds may run side by side.

Methods

Begin()

Called once after every module is initialised and validated, before founders spawn, in hierarchy order: place initial content here (the first food items), when it depends on other services (cover).

public virtual void Begin()

Remarks

Not called when the editor only validates. Draw random numbers from a named stream, e.g. World.Random.Get("world/" + ServiceName) for the map (RAND-04).

Initialize()

Called by the World in a fixed order, before any animal exists (ARCH-04).

public virtual void Initialize()

Remarks

Look up what you need here, by role or name (Service<T>(), Phase<T>()), and reset your own state: the same object starts every run of the World. A service is initialised before the species' modules; a phase after them.

Write and close your files here (the run recorder does). An exception is logged and the other modules still hear the stop.
